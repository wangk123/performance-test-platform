## 0. 前提澄清：计划文档的内容模型（重要）

**Pretty 不是 Markdown 预览，而是结构数据的展示；每个模块都支持结构化编辑。** 这是本方案的前提语义：

| 概念 | 语义 |
|------|------|
| Pretty 视图 | 面向结构化模块的展示层：受控章以表格/清单/卡片等结构形态呈现数据，叙述章以文本形态呈现 |
| Markdown 视图 | 文档源文本（`plan.body`）的查看/整篇编辑入口 |
| 受控模块 | 模板受控字段，编辑走**结构化编辑**（表单/行内表格/清单勾选），而非裸文本 |
| 叙述模块 | 自由文本，编辑走文本编辑器 |

现状与语义的差距（实现时注意）：`PlanDetailDocument.vue` 的 Pretty 分支目前仅「五、测试约束」（ChecklistView）与「七、场景设计」（ScenarioDesignModule）是结构化模块，其余章节暂以 `MdPreview` 渲染、`PlanSectionEditor.vue` 亦为整章 MdEditor 弹窗——这是向结构化模型迁移的过渡态。**本方案的展示层优化不依赖、也不阻塞该迁移**：P0/P1 的布局与视觉改造在两种形态下均成立；涉及编辑入口的条目（P1-4、P1-6）已按「结构化编辑」语义表述，迁移时无需返工。

## 1. 问题结论

页面「说不上来哪里不对劲」的体感来自三个结构性根因，而非控件质感：

| # | 根因 | 关键证据 |
|---|------|---------|
| R1 | 信息大量重复且不一致 | `CCCC`×3（面包屑/页头/文档区）；`草稿`×3（页头徽标/步骤名/状态 chip）；`revision 1`×3（页头/文档区/工具栏）；负责人/场景/更新时间在页头与文档区各出现一次且**字段顺序不同** |
| R2 | 双进度隐喻同屏冲突 | 步骤条（草稿→评审→执行→报告→发布）与 Tabs（文档/评审/报告/发布）词汇几乎重合，用户需自行心算两者关系；步骤 1 名称与状态 chip 均为「草稿」 |
| R3 | 首屏全是壳 | 内容开始前需穿过 面包屑→页头卡→步骤条卡→Tab 条→工具条→文档标题卡 约 410px，1080p 首屏几乎无正文 |

伴生问题：强调色语义过载（青色同时承担主按钮/当前阶段/导航选中/Tab 选中/切换选中/TOC 当前章/「受控」徽标×6/草稿徽标 ≥5 种语义）；文档被切成 12 个边框卡片，「编辑章节」独占一行先于内容出现；表格拉满全宽、列宽与内容无关。

## 2. 目标与非目标

**目标**
1. 内容前 chrome（页头+导航+工具）总高度 ≤ 250px（现 ~410px）。
2. 同一字段在同屏内只出现一次；流程状态只有一种表达。
3. 强调色只保留两个语义：主操作按钮、当前流程阶段。
4. 文档 Tab 阅读体验回归「一篇文档」，编辑入口不打断阅读动线。

**非目标**
- 不改业务流程与数据模型（阶段、评审、发布逻辑不变）。
- 不动暗色主题机制（全部沿用 base.css 令牌，暗色零额外成本）。
- 不涉及评审/报告/发布三个 Tab 内部重构（另立任务）。

章节卡 ×11（每卡：标题/分割线/              ─────────────────────────—
  「编辑章节」行/内容）                     二、测试目的与指标 [受控]     [✎ 编辑]

## 4. 改造项清单

### P0 · 结构减负（对症「说不出的不舒服」）

| # | 改造项 | 现状 → 改法 |
|---|--------|------------|
| P0-1 | 元数据只出现一次 | 删除文档区顶部「CCCC+meta」整卡；页头 meta 为唯一来源，统一字段顺序：负责人 → 场景 → 更新于（revision 只保留工具栏一处，以 mono 徽标呈现） |
| P0-2 | 流程状态单一表达 | 大步骤条卡降级为**页头右侧紧凑步骤条**（节点 20px、标签 11px、无状态 chip）；阶段状态并入页头标题旁的徽标（草稿/待评审/…）。Tabs 语义收窄为「看什么」，与阶段解耦 |
| P0-3 | 修「草稿×3」 | 阶段名固定为：策略/评审/执行/报告/发布；「草稿」只是状态徽标，不再作阶段名 |
| P0-4 | Tabs 与工具条合并 | 两行合一行 44px：左 Tabs，右 Pretty/Markdown 切换 + revision 徽标 + 执行设置按钮 |
| P0-5 | 首屏预算 | 由 P0-1/2/4 自然达成：chrome ~230px（目标 ≤250px），首屏即见第一章正文 |

### P1 · 视觉系统

| # | 改造项 | 改法 |
|---|--------|------|
| P1-1 | 强调色预算 | `--accent` 仅用于：①主操作按钮（提交评审）②当前流程阶段节点/状态徽标 ③正文内文字链。Tab 选中 = 墨色 600 + 2px 墨色下划线；TOC 选中 = 墨色 500 + `--surface-soft` 底 + 3px 墨色左条；Pretty/Markdown 选中维持中性白底浮起 |
| P1-2 | 「受控」徽标降噪 | TOC 不再用青色描边徽标（×6 是最大噪声源）：受控章仅显示 12px 灰锁形图标，叙述章不标；章标题旁保留一个中性灰「受控」小标签说明模板受控属性 |
| P1-3 | 文档回归一篇 | 11 个章节卡合并为**一个白卡容器**；章与章以 24px 留白 + 发丝线（`--line` 60% 透明）分隔；去掉章节内部的标题分割线与容器嵌套 |
| P1-4 | 编辑入口让位阅读 | 「编辑章节」独立行取消，改为章节标题行右端的 `✎ 编辑` 幽灵按钮（12px，`--muted`，hover 才转 accent）。语义按模块形态分流：**受控结构化模块 → 结构化编辑**（表格行内增删改/抽屉表单，同 ChecklistView、ScenarioDesignModule 模式）；叙述模块 → 文本编辑。现 `PlanSectionEditor` 的整章 MdEditor 弹窗是过渡态，迁移为按模块类型分发编辑器时入口位置不变 |
| P1-5 | 字号阶梯 | 文档标题 20/600（不再在文档区重复出现）→ 章标题 17/600 → 小节 15/600 → 正文 14/1.7 → 辅助 12；层级靠对比而非分割线 |
| P1-6 | 表格按内容定宽 | 表格 `max-width: 880px` 不再拉满；列宽按内容分配（交易列宽、指标/目标值/口径窄）；行高 40px、表头 36px；表头上方加 12px 弱说明「示例数据 · 提交评审前替换」，(示例) 前缀改弱灰色，让「模板态」显得有意为之。表格是结构化模块的数据展示：可编辑态在表尾提供 ghost「+ 添加」行（虚线、弱灰），点击走结构化行编辑，不打开整章文本弹窗 |

### P2 · 打磨

| # | 改造项 | 改法 |
|---|--------|------|
| P2-1 | 紧凑步骤条连接线 | 连接线贯穿节点圆心、18px 长、2px 粗；整组右对齐页头，消灭右半死空间 |
| P2-2 | 执行设置按钮语义 | 文案去掉括号副文案，「环境检查」作为按钮内 12px 弱化后缀或 tooltip |
| P2-3 | meta 可扫读 | 标签 `--muted`、值 `--ink`，项间以 `·` 分隔 |
| P2-4 | 空状态产品化 | 「场景 0」后跟「去绑定」文字链；空章节占位文案保留灰色引导句，配合标题行「编辑」即得入口 |
| P2-5 | revision 徽标 | 工具栏 `revision 1` 改为 mono 12px、`--surface-soft` 底、`--radius-sm` 圆角的轻徽标 |

## 5. 布局规格（效果图采用值）

- 画布 `--canvas:#f4f6f8`；卡片 `--surface:#fff`、边 `--line:#e2e8ee`、圆角 8px、阴影 `0 1px 2px rgba(26,35,50,.04)`。
- 页头卡：padding 16px 20px；左列（标题 18/600 + 徽标；meta 13px），右列上为按钮组、下为紧凑步骤条。
- 紧凑步骤条：节点 20px 圆、编号 11px；当前节点 `--accent` 实心白字，未达节点白底 `--line-strong` 边灰字；标签 11px，当前 `--plan-accent-text`，其余 `--muted`；连接线 18×2px `--line-strong`。
- 合并行：高 44px 白卡；Tab 14px；segmented 高 28px；按钮高 28px。
- 文档主卡：padding 28px 36px；TOC 列 208px + 主列 1fr，gap 16px。
- TOC 项：13px，行高 26px，左内边距 8px + 3px 左条（选中态）；受控章右侧 12px 锁图标（`--line-strong` 色）。

## 7. 验收口径

1. 同屏搜索 `CCCC`/`草稿`/`revision` 各 ≤1 处（面包屑中的计划名除外）。
2. 首个章节标题距视口顶 ≤ 280px（1080p；效果图实测 ~270px）。
3. 全页 accent 色相仅出现在：提交评审按钮、当前阶段节点、状态徽标、正文文字链、TOC/Tab 选中态之外不得出现。
4. 既有暗色主题切换零回归（仅用令牌，不引入裸 hex）。
